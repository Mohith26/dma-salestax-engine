# TaxGrid

A sales and use tax determination engine I built to see how much of the hard part of transaction tax (layered jurisdictions, taxability quirks, effective-dated rates, penny rounding) I could get exactly right, and then prove it with an independent oracle instead of just trusting my own tests.

Everything in `data/` is invented. The 15 states, 225 jurisdictions, rates, taxability rules and exemption certificates are fictional, generated by `scripts/gen_dataset.py` with a fixed seed. Nothing here maps to any real tax authority, and this should never be used to compute actual tax.

## Why I built it this way

Tax math looks trivial (price times rate) until you stack four jurisdictions with different rounding conventions on one line, date the rates, and add category exemptions with per-item price thresholds. A one cent disagreement is a real bug in this domain, so the engine works exclusively in integer cents and integer basis points. There is no float anywhere in the money path.

The verification idea is the part I care about most: a second, deliberately alien implementation (`src/taxgrid/oracle.py`) recomputes every determination. It parses the raw JSON itself, compares ISO date strings lexicographically instead of converting to ordinals, and rounds with `decimal.Decimal` quantization instead of the engine's quotient and remainder arithmetic. Both were run over 1,000,000 seeded random invoice lines: 0 mismatches. On top of that there are 12 golden invoices whose expected totals I worked out by hand on paper before running anything (the arithmetic is preserved in `golden/golden_invoices.json`), plus an exhaustive rounding boundary sweep that checks every exact half-cent tie under all three rounding modes.

## What a determination does

Each invoice line runs through four stages, and every stage writes to an audit trail:

1. Situs resolution. Origin sourced states use the ship_from city for intrastate sales; destination states and all interstate sales use ship_to. Use tax (`transaction_type: "use"`) always accrues at the destination and is flagged as a self assessed accrual rather than collected tax.
2. Taxability. A state by category matrix with three rule kinds: taxable, exempt (with a reason), and per-item price thresholds (one state exempts clothing under 110.00 per item, another under 175.00). Thresholds apply to the unit price, not the extended amount.
3. Exemption certificates. Certificates have a kind, a category scope and a validity window. An expired or out of scope certificate is recorded in the audit trail and ignored.
4. Rate stack and rounding. State, county, city and any special districts covering the situs city each contribute a rate looked up by effective date, and each jurisdiction rounds its own tax to whole cents under its documented mode (half up, half down, or half even).

The audit trail lists the situs decision, the taxability rule applied, certificate evaluation, and one entry per jurisdiction with rate, base, rounding mode and tax in integer cents. The intent is that a human could reproduce any line total from the audit alone.

## Running it

```
python3 -m venv .venv && .venv/bin/pip install -U pip
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest tests/ --color=no -q --cov=src/taxgrid
.venv/bin/python scripts/verify_oracle.py 1000000 42   # engine vs oracle
.venv/bin/python scripts/bench.py 500000 7             # throughput
.venv/bin/python scripts/bench_api.py 2000             # API latency
.venv/bin/uvicorn --app-dir src taxgrid.api:app        # serve the API
```

The API has one interesting endpoint, `POST /determine`, which takes an invoice and returns the full determination with per-line audit trails:

```json
{
  "date": "2023-01-15",
  "ship_from": "CI-CD-00-0",
  "ship_to": "CI-MW-00-0",
  "lines": [{"category": "clothing", "unit_price_cents": 11000, "quantity": 1}]
}
```

Measured numbers and reproduce commands live in RESULTS.md.

## Layout

```
data/       committed invented dataset (jurisdictions, taxability, certificates)
golden/     hand computed golden invoices with the arithmetic in the notes
src/taxgrid engine, oracle, dataset loader, rounding, FastAPI app
scripts/    dataset generator, oracle verification, benchmarks
tests/      88 pytest tests
results/    JSON output of the measurement runs
```

## Limitations

- The dataset is invented. Real jurisdictions have vastly messier boundaries, overlapping districts, and rates that do not come from a seeded generator.
- There is no address geocoding. Situs starts from a known city id; mapping street addresses to jurisdictions is a separate hard problem I did not touch.
- Taxability is decided at the state level for the whole stack. Real systems support local-only taxability overrides (a city taxing something its state exempts); mine does not.
- Threshold semantics are all or nothing per item. Some real rules tax only the portion above the threshold.
- No VAT, no filing or returns, no credits for tax paid to another state on the use tax path, no UI.
- Certificates are invoice level and category scoped. Real certificate management (jurisdiction specific forms, renewal, drop shipment scenarios) is far richer.
- Benchmarks are single threaded on my laptop (Apple silicon); see RESULTS.md for the exact context.
